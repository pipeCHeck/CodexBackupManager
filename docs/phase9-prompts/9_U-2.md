## 1. 이번 범위 (9_U-09)

### (가) 메인 트리 키보드로 체크
- 지금은 메인 트리 체크박스가 포커스를 받지 않아 키보드로 체크할 수 없다. 대화 보기와 분리하려고 이렇게 되어 있다.
- 선택된 줄(대화 또는 프로젝트)에서 **Space**를 누르면 그 줄의 체크를 바꾼다. 마우스로 체크박스를 누른 것과 같은 코드 경로를 쓴다.
  - 프로젝트 줄이면 그 프로젝트 전체(숨은 대화 포함, 기존 규칙과 같음)
  - 대화 줄이면 그 대화
- Space는 대화 보기(오른쪽 내용 열기)를 바꾸지 않는다. 화살표 이동과 Enter 같은 기존 키 동작은 그대로 둔다.
- 검색 칸에 포커스가 있을 때의 Space는 글자 입력이다(트리에만 적용).
- 가져오기 화면 트리가 이미 Space를 지원하면 같은 방식으로 맞추고, 아니면 이번에는 메인만 한다(보고).

### (나) 내보내기 완료 창에 경고 내용 표시
- 지금 완료 상태 문구에 "(경고 N건)"만 나오고 무슨 경고인지 알 수 없다.
- 완료 창에 "경고 N건" 영역을 두고 항목을 사용자 말로 보여 준다(경고가 없으면 숨김).
  - 경고 원문이 경로·제목을 담을 수 있으면 화면에는 보여도 되지만 로그에는 남기지 않는다(기존 규칙).
  - 경고 종류(BackupWriter/ExportPlan이 내는 것)를 조사해 종류별 사용자 문구를 정하고 표로 보고한다.
- 텍스트 목록 파일(txt)에도 "경고" 절을 넣을지 정해 보고한다(권장: 넣음, 한 줄씩).

### (다) Restore 층 사용자 메시지의 "Snapshot" → "복구 지점"
- 사용자에게 보이는 Restore 층 메시지에서 "Snapshot"을 "복구 지점"으로 바꾼다. 예: "복구용 Snapshot을 만들지 못해…" → "복구 지점을 만들지 못해…"
- ID를 보여 주는 곳(예: "복구 지점(…ID…)")은 ID는 그대로 두고 앞말만 바꾼다.
- 로그 문자열과 코드 식별자는 바꾸지 않는다.
- 바꾼 문구를 기대값으로 가진 테스트도 함께 바꾸고 목록을 보고한다. 문구의 뜻이 바뀌면 안 된다.

### 테스트
- (가)
  - 대화 줄 Space → 체크 토글, 선택 수 반영
  - 프로젝트 줄 Space → 전체 토글
  - 검색 칸 Space → 글자 입력(토글 없음)
  - Space가 오른쪽 대화 보기를 바꾸지 않음
- (나): 경고 0건이면 영역 숨김, N건이면 항목 표시, txt 경고 절(넣는 경우), 로그에 경고 원문 없음
- (다): 바꾼 문구 테스트
- 렌더 바인딩 오류 0, 회귀 전체 GREEN(가짜 codex 실행 중 1회 + 없이 1회)

## 3. 안전 규칙
- 실제 C:\Users\User\.codex와 실제 Snapshot 폴더에는 쓰지 않는다. 작업 전후 4개 파일 SHA-256을 비교해 보고한다(state_5.sqlite, session_index.jsonl, .codex-global-state.json, config.toml). 사용자가 Codex를 쓰는 중이면 열지 않았다는 사실과 수정 시각만 보고한다.
- 테스트에서 [새로고침] 등 자동 탐지가 실제 .codex를 읽지 않도록 반드시 harness 사본으로 연결한다(9_U-1에서 한 번 실제 .codex를 읽기 전용으로 연 일이 있었다).
- 앱을 띄워 볼 때는 보기만 한다. 내보내기는 스크래치 폴더로만 한다. [가져오기]·[되돌리기]·[삭제]·[정리]·[사이드바에 표시]·[이전 상태로 복구]는 누르지 않는다.
- 사용자가 실험 빌드(artifacts\*)나 개발 빌드 앱을 실행 중일 수 있다.
  - 그 프로세스를 종료하지 않는다. artifacts 폴더는 건드리지 않는다.
  - 빌드가 잠기면 저장소를 bin/obj/.git 없이 스크래치로 복사해 빌드·테스트하고 그렇게 보고한다.
- 로그에 경로·제목을 남기지 않는다. 빌드 경고 0 · 오류 0. 불확실하면 추측하지 말고 보고서 7번에 질문으로 남긴다.
