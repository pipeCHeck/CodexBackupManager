## 1. 배경 (관리 대화방 점검 결과)

9_1b 점검은 통과다. 복제본으로 확인한 Case 0~4가 전부 기대대로 동작했다. 등록됐지만 대화 0개인 프로젝트 연결, 레거시 ID 프로젝트, 미등록 폴더 모두 포함이다.
이번 단계는 "사용자가 가져올 대화를 고르는" 핵심 로직을 만든다.

- 지금은 Preview의 대화가 전부 Plan에 들어간다.
- Diverged(RequiresDecision)나 Unverifiable(Blocked)이 하나라도 있으면 ImportPlan.IsApplyReady가 false가 되고, RestoreOperationPlanner도 계획 전체를 거부한다.
- 목표: 사용자가 충돌 대화의 체크를 해제하면 나머지는 적용할 수 있어야 한다. 단, 선택한 대화에 꼭 필요한 조상(분기 원본)이 충돌이면 계속 막는다.
- 체크를 바꿀 때마다 Plan을 만들면 안 된다. ImportPlanBuilder는 backup 전체를 스트리밍 해시한다. 선택 요약은 메모리에서 계산하고, Plan은 [가져오기] 시점에 한 번만 만든다.

**9_2-02** ImportSelection.Compute(preview, choices) → SelectionSummary (순수 로직, 파일 I/O는 Directory.Exists뿐)
- 대화별 결과: 최종 동작(Import/Update/NoOp/Skip), SkipReason, 선택 가능 여부와 불가 사유, 사용자 포함 여부, 조상 자동 포함 여부, 소속 프로젝트의 목적지(ProjectTarget)
- 선택 가능 규칙(설계 §7.4)
  - 가능: New, IncomingAhead(.jsonl.zst가 아닐 때만. IsCompressedRollout이면 불가, Restore가 압축 Update를 막기 때문)
  - 불가: Identical(9_3 전까지), LocalAhead, Diverged, Unverifiable
  - 선택 불가 대화가 IncludedThreadIds에 들어와도 무시하고, 요약 경고에 남긴다.
- 조상 closure
  - 포함된 대화의 RequiredAncestorThreadIds를 자동 포함한다. 사용자가 끌 수 없다.
  - 자동 포함된 조상의 동작은 Preview의 PlannedAction을 따른다(New면 Import, Identical이면 NoOp 등).
  - 어떤 포함 대화에도 필요 없는 dependency-only 대화는 Skip(NotSelectedDependencyNotNeeded)이다.
- 차단 판정
  - closure 안에 RequiresDecision(Diverged)이나 Blocked(Unverifiable)가 있으면 CanApply=false다.
  - 사유에는 어떤 포함 대화가 어떤 조상 때문에 막혔는지 thread ID로 남긴다.
  - closure 밖(제외됨)의 충돌은 막지 않는다.
- 요약: Import 수, Update 수, NoOp 수, Skip 수, 조상 자동 포함 수, "기타 대화로 들어갈" 쓰기 대상 수(목적지 Kind가 Uncategorized인 Import), 적용 가능 여부와 사유 목록, 쓸 것이 0개인지와 그 사유
  - "0개인 사유" 예: 선택한 대화가 모두 이미 이 PC에 있음 / 선택한 대화 없음 / 모두 선택 불가

**9_2-04** ImportPlanBuilder.Build(preview, backupFilePath, choices) 오버로드
- ImportSelection과 **같은 규칙(같은 코드 경로)**으로 Plan을 만든다. 요약과 Plan이 서로 다른 판단을 하면 안 된다.
- 프로젝트별 ResolvedTarget은 decision 기준이다. PathStatus는 decision에 FolderPath가 있으면 ManuallyLinked, 아니면 자동 판정 규칙을 따른다(9_1b 규칙).
  TargetProjectPath는 LinkExisting이면 연결 루트, 아니면 null이다(호환 의미 유지).
- HasBlockingIssues와 HasUnresolvedDivergence는 closure 기준으로 계산한다.
- backup identity pinning(06_03)은 유지한다. SourceBackupIdentity와 현재 파일 해시가 다르면 null을 반환한다.
- 기존 Build(preview, path) 시그니처는 UserChoices=null로 **지금과 완전히 같은 Plan**을 만든다.

**9_2-05** Diverged/Unverifiable 제외 시 적용 가능
- 9_2-04/9_2-21의 결과로, 충돌 대화를 뺀 Plan은 IsApplyReady=true가 되고 RestoreExecutor.Apply가 나머지를 적용한다.

**9_2-06** 폴더 변경 재판정 함수
- UI가 폴더를 바꿀 때 부를 순수 함수를 제공한다(예: ImportSelection.ResolveTarget(project, decision, directory)).
- Plan 생성 없이 메모리와 Directory.Exists만 쓴다.

**9_2-21** 제외 대화를 Preflight/Planner/Validator에서 제외
- SkipReason이 UserExcluded나 NotSelectedDependencyNotNeeded인 대화는 다음에서 모두 빠진다.
  - ImportPlanPreflightValidator의 사전조건 검사(MustNotExist/MustExist, revision 비교)
  - RestoreOperationPlanner의 쓰기 대상(rollout 파일 생성·append, threads INSERT/UPDATE)과 "예상치 못한 PlannedAction" 거부
  - RestoreValidator의 사후 검증
- 그래서 제외 대화의 로컬 상태가 바뀌어도 나머지 적용을 막지 않는다.
- LocalAhead의 Skip(SkipReason=LocalAhead)은 **지금 동작을 그대로 유지**한다.
- 백업 rollout 파일의 소유 thread가 Skip이면 그 파일은 쓰지 않는다. 조상이 Import인 경우만 조상 파일을 쓴다(기존 규칙 확인).
