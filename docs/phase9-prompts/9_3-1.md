## 1. 배경 (관리 대화방 실측, 읽기 전용)
- 이 PC의 활성 대화 421개 중 DB `threads.project_id`가 채워진 것은 4개뿐이다. 모두 이 앱이 가져온 대화다.
- Desktop이 직접 정한 대화 소속 72건은 global-state `thread-project-assignments`에만 있다(`{projectKind:"local", projectId:<레거시 ID>}`). 그 대화들의 DB `project_id`는 NULL이다.
- `projectless-thread-ids` 11개도 DB `project_id`가 NULL이다.
- 9_0-A에서 확인했다: 배정이 없는 대화는 DB `project_id`만 채워도 Desktop이 그 프로젝트 아래에 보여 준다.
- 배정이나 projectless에 들어 있는 대화를 DB만 바꾸면 Desktop이 어느 쪽을 따를지 **확인되지 않았다**. 그래서 V1은 그런 대화를 옮기지 않는다. global-state의 대화 소속 키도 쓰지 않는다.
- 9_5-1에서 "이어받기만 가는 CreateNew 목적지로는 프로젝트를 만들지 않는다"고 정했다. 이번에 연결 변경이 생기므로 이 규칙을 넓힌다(9_3-05).

## 2. 이번 범위

### 9_3-00 대상 판정 (Backup 층, 순수 규칙)
- 연결 변경 후보는 다음을 모두 만족하는 백업 대화다.
  - 이 PC에 같은 thread가 있다.
  - Relation이 Identical, IncomingAhead, LocalAhead 중 하나다(Diverged 제외).
  - 보관됨(archived)이 아니다.
  - 그 백업 프로젝트의 목적지가 LinkExisting(DB ID 있음) 또는 CreateNew다.
  - 이 PC에서의 현재 위치(DB `project_id`, 또는 기타 대화)가 목적지와 다르다.
- 제외(체크박스를 끄고 이유를 보여 준다)
  - global-state `thread-project-assignments`에 그 thread가 있다 → "Codex 데스크톱 앱이 이 대화의 위치를 따로 기록하고 있어 이 앱에서 옮기지 않습니다. Codex에서 직접 옮겨 주세요."
  - `projectless-thread-ids`에 있다 → 같은 문구
  - global-state를 읽지 못했거나 9_5a 게이트에 실패했다 → "Codex 데스크톱 앱 상태 파일을 확인하지 못해 옮기지 않습니다."
  - 목적지가 Uncategorized다(기타 대화로 "옮기기"는 V1 범위 밖) → 체크박스 숨김
- 판정 결과(가능/불가 사유 enum)를 ImportPreview 또는 Selection 결과에 담는다. 위치를 정하고 이유를 보고한다.
  읽기 전용 입력(배정·projectless 목록)은 카탈로그를 만들 때 함께 읽는다.

### 9_3-01 화면: "📁 연결만 변경" 체크
- 후보 대화 행에 체크박스 "📁 이 프로젝트로 옮기기"를 둔다. 기본은 해제다. 일반 가져오기 체크와 구분되게 한다.
  IncomingAhead 대화는 이어받기 체크와 따로 고른다(둘 다 가능).
- 불가 사유가 있으면 흐린 체크박스와 이유 한 줄(툴팁 아님)을 보여 준다.
- ImportUserChoices에 `RelinkThreadIds`(설계 §5.2에 예고된 이름)를 추가한다. 하위 호환을 위해 기본은 빈 집합이다.
- 하단 요약: "연결 변경 N개", 확인 대화상자: "프로젝트 옮기기 N개: '제목' 기타 대화 → '○○'"
- 버튼 문구: 쓸 것이 연결 변경뿐이어도 [가져오기]를 켠다. 문구 예: "대화 0개 가져오기 · 1개 옮기기". 자연스러운 문구를 정해 보고한다.

### 9_3-02 Plan과 Planner
- ImportPlan에 연결 변경 목록을 싣는다(대상 thread, 계획 시점의 현재 project_id·cwd, 목적지 키).
- Planner: `PlannedThreadProjectLink(ThreadId, ExpectedProjectId (nullable), ExpectedCwd, NewProjectId, NewCwd)`
  - 목적지가 LinkExisting이면 그 DB ID와 그 프로젝트의 등록 루트 표기(9_1-16 규칙)
  - CreateNew면 같은 Plan의 PlannedProjectCreate의 NewProjectId와 RootPathDisplay
- fresh 재판정: Apply 시점의 fresh 카탈로그에서 다시 판정해 후보 조건이 깨졌으면 거부한다.
  - 거부하는 경우: 배정에 들어감, 위치가 계획과 다름, 보관됨, Diverged가 됨
  - 거부는 NotReady이고 쓰기 0이다.

### 9_3-03 Writer
- 기존 Apply와 같은 SQLite 트랜잭션 안에서, 프로젝트 생성 뒤·thread INSERT와 같은 단계에서 실행한다.
  - `UPDATE threads SET project_id=@new, cwd=@newCwd WHERE id=@id AND project_id IS @expected AND cwd=@expectedCwd`
  - 영향 행이 정확히 1이 아니면 예외 → Rollback(TOCTOU)
- `updated_at_ms`와 다른 컬럼은 바꾸지 않는다. rollout 파일도 건드리지 않는다.
- Snapshot 대상: state DB(+WAL/SHM). 새 프로젝트를 만들면 기존처럼 global-state도 넣는다.

### 9_3-04 결과 화면
- "옮김: '제목' 기타 대화 → '○○'"(새 프로젝트면 "→ 새로 만든 프로젝트 '○○'")
- 사후 검증(RestoreValidator): 대상 thread의 project_id·cwd가 새 값이다. fresh catalog에서 그 대화가 목적지 그룹 아래 있다.

### 9_3-05 새 프로젝트 생성 규칙 확장
- 새로 가져올 대화가 없어도, 연결 변경 대화가 가는 CreateNew 목적지면 프로젝트를 만든다.
- ImportSelection 요약의 NewProjects, Planner의 PlanProjectCreates, 결과 화면이 같은 규칙(NewProjectGrouping)을 쓴다.
- 이어받기만 가는 목적지로는 여전히 만들지 않는다(9_5-1 규칙 유지).

### 9_3-06 계획 뒤 global-state 변경 감지
- 연결 변경이 있는 Plan은 프로젝트를 만들지 않더라도 계획 시점 global-state SHA-256을 고정한다(9_5a의 GlobalStateExpectedSha256과 같은 방식).
- Snapshot 직후, 트랜잭션 안에서 다시 비교한다. 바뀌었으면 거부하거나 Rollback한다. global-state에는 이 단계 때문에 쓰지 않는다(새 프로젝트의 레거시 항목은 9_5a 그대로).

## 4. 안전 규칙
- **실제 C:\Users\User\.codex에는 절대 쓰지 않는다.** 작업 전후 4개 파일 SHA-256을 비교해 보고한다(state_5.sqlite, session_index.jsonl, .codex-global-state.json, config.toml).
  사용자가 Codex를 쓰는 중이면 값이 바뀔 수 있다. 그때는 열지 않았다는 사실과 수정 시각만 보고한다.
- 실제 .codex에서 후보 판정을 읽기 전용으로 확인해 보는 것은 괜찮다. 출력은 개수와 enum만 한다(제목·ID 금지).
- 앱을 띄워 보더라도 [가져오기]·[새 폴더 만들기]·[사이드바에 표시]는 누르지 않는다.
- 쓰기는 RestoreExecutor 파이프라인 안에서만 한다. 확인하지 않은 컬럼을 쓰지 않는다(CLAUDE.md §33).
- 로그에 경로·제목·이름·thread ID를 남기지 않는다(개수와 결과 enum만).
- 복제본을 CODEX_HOME으로 codex.exe 실행 금지.
- 사용자가 실험 빌드(artifacts\test-9_0C 등)나 개발 빌드 앱을 실행 중일 수 있다.
  - 그 프로세스를 종료하지 않는다. artifacts 폴더는 건드리지 않는다.
  - 빌드가 잠기면 저장소를 bin/obj/.git 없이 스크래치로 복사해 빌드·테스트하고 그렇게 보고한다.
- TDD: 안전 거부 경로(TOCTOU, 배정 제외, 계획 뒤 변경)는 RED를 먼저 본다. 빌드 경고 0 · 오류 0. 불확실하면 추측하지 말고 보고서 7번에 질문으로 남긴다.
