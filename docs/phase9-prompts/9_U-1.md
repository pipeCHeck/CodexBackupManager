## 2. 이번 범위

### 9_U-01 메인 화면 검색
- 메인 목록 위에 검색 칸을 둔다. 자리 표시는 "대화 제목 또는 프로젝트 이름 검색"이다.
- 규칙은 가져오기 화면(9_2-33 `IsShownBySearch`)과 같다.
  - 대화 제목 부분 일치 → 그 대화와 부모 프로젝트
  - 프로젝트 이름 일치 → 그 프로젝트의 대화 전부
  - 앞뒤 공백 제거, 대소문자 무시
  - 가능하면 같은 함수를 함께 쓴다(공용 위치로 옮겨도 된다).
- 검색은 표시만 바꾼다. 체크 상태와 "선택한 대화 N / 전체"는 바뀌지 않는다.
  - 숨은 대화도 선택은 유지되고 내보내기에 포함된다. 사용자가 헷갈리지 않게 검색 중이면 "검색 중: N개 표시" 같은 표시를 두고, 방법을 보고한다.
  - [전체 선택]/[선택 해제]가 검색 중에 보이는 것만 대상인지 전체 대상인지 정하고 화면에 분명히 한다.
    권장: 지금처럼 전체 대상, 버튼 툴팁에 명시.
- 검색어를 지우면 원래대로 돌아간다. 새로고침이나 Codex 폴더를 바꾼 뒤에도 검색어 처리가 자연스러워야 한다(유지 또는 초기화를 정해 보고).
- 대화 내용 보기(오른쪽)와 검색이 서로 꼬이지 않게 한다. 선택한 대화가 검색으로 숨겨져도 오른쪽 내용은 유지해도 된다.

### 9_U-02 (오류) 메인 하단 안내 문구
- "Codex 원본 데이터는 읽기 전용으로만 접근합니다."를 사실에 맞게 바꾼다.
  - 예: "목록 보기·내보내기는 Codex 데이터를 바꾸지 않습니다. 가져오기·되돌리기는 복구 지점을 만든 뒤에만 바꿉니다."
- 너무 길면 한 줄 요약 + 툴팁으로 둔다. README·dist-readme 문구와 같은 뜻이어야 한다.

### 9_U-03 (오류) 가져오기 화면 좁은 폭 말풍선 잘림
- 820px 폭에서 오른쪽 대화 내용 말풍선이 패널 안에서 줄바꿈되게 고친다. 메인 화면 대화 보기도 같은 문제가 있는지 확인한다(같은 템플릿을 쓴다).
- 렌더 테스트로 좁은 폭(예: 820×700)에서 말풍선 오른쪽 끝이 패널 안에 있는지 확인한다.

### 9_U-04 기본 화면의 기술 정보 정리
- 상단 정보 줄(Desktop/CLI/Sessions/Threads/archived)은 [상세 정보] 안으로 옮기거나, 쉬운 말로 줄인다.
  - 기본에 남길 것: "Codex 버전 26.928" 정도. 나머지는 상세.
- 목록 머리 "rollout 파일 · 스캔 ms / 전체 ms"는 상세로 옮긴다. 기본은 "프로젝트 N개 · 대화 N개"다.
- "Codex Home" 라벨은 "Codex 데이터 폴더"로 바꾼다. 경로 표시는 그대로 둔다.
- 개발자 진단 정보는 지우지 말고 [상세 정보]에서 볼 수 있게 남긴다.

### 9_U-05 처음 쓰는 사람을 위한 안내와 툴팁
- 메인 오른쪽 빈 영역(대화를 고르지 않았을 때)에 짧은 사용 순서를 보여 준다. 예:
  ① 내보낼 대화나 프로젝트를 체크하고 [백업 내보내기]
  ② 다른 PC에서는 Codex를 종료한 뒤 [백업 가져오기]
  ③ 목록에서 대화를 누르면 여기에 내용이 보입니다
- 메인 하단 버튼에 툴팁을 단다. 각 버튼이 무엇을 하는지와, Codex 데이터를 바꾸는지 여부를 쓴다.
  - 대상: Codex 폴더 선택, 새로고침, 백업 내보내기, 백업 가져오기, 가져오기 기록
- 비활성 버튼에는 왜 비활성인지 알 수 있게 한다. 예: 대화를 고르지 않았을 때 [백업 내보내기].

### 9_U-06 상태 문구 정리
- '길다' 표현을 사용자 말로 바꾼다(뜻은 그대로).
  - "이 PC 쪽이 더 깁니다. 건너뜁니다." → 예: "이 PC에서 더 이어서 쓴 대화입니다. 그대로 두고 건너뜁니다."
  - "이 PC에 있지만 백업이 더 깁니다. 뒤에 이어붙입니다." → 예: "백업에 이 PC보다 뒤의 내용이 있습니다. 이 PC 대화에 이어 붙입니다."
  - 압축 기록 관련 문구도 같은 식으로 바꾼다.
- 내보내기 완료 상태 문구에서 처리 시간(ms)을 뺀다(로그에는 남겨도 된다).
- "Snapshot" 표기를 통일한다. 사용자 화면에서는 "복구 지점"을 쓰고, 영어는 필요한 곳에 처음 한 번만 괄호로 쓴다.
- 이미 테스트로 고정된 문구를 바꾸면 테스트 기대값도 함께 바꾸고 목록을 보고한다.

### 9_U-07 목록 트리

## 4. 안전 규칙
- 실제 C:\Users\User\.codex와 실제 Snapshot 폴더에는 쓰지 않는다. 작업 전후 4개 파일 SHA-256을 비교해 보고한다(state_5.sqlite, session_index.jsonl, .codex-global-state.json, config.toml). 사용자가 Codex를 쓰는 중이면 열지 않았다는 사실과 수정 시각만 보고한다.
- 앱을 띄워 볼 때는 보기만 한다. [가져오기]·[새 폴더 만들기]·[사이드바에 표시]·[되돌리기]·[삭제]·[정리]·[이전 상태로 복구]는 누르지 않는다. 내보내기를 해 볼 때는 결과 파일을 스크래치 폴더에만 저장한다.
- 테스트에서 자동 탐지가 실제 .codex를 읽지 않도록 harness 사본으로 연결한다.
- 사용자가 실험 빌드(artifacts\*)나 개발 빌드 앱을 실행 중일 수 있다.
  - 그 프로세스를 종료하지 않는다. artifacts 폴더는 건드리지 않는다.
  - 빌드가 잠기면 저장소를 bin/obj/.git 없이 스크래치로 복사해 빌드·테스트하고 그렇게 보고한다.
- 로그에 경로·제목·검색어를 남기지 않는다. 빌드 경고 0 · 오류 0. 불확실하면 추측하지 말고 보고서 7번에 질문으로 남긴다.
