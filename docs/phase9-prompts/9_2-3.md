## 1. 배경 (관리 대화방 점검 결과)

9_2-2 점검은 통과다. 관리 대화방이 **실제 앱을 UI 자동화로 띄워** 사용자가 원래 겪은 백업(이미 이 PC "기타 대화"에 있는 대화 1개)을 열어 캡처했다. 결과는 다음과 같았다.
- 버튼 "대화 0개 가져오기" 비활성, "선택한 대화는 모두 이미 이 PC에 있습니다. 가져올 것이 없습니다." 표시
- "원본 폴더가 이 PC에 없습니다…" 안내 표시
- 820px 폭에서도 겹침 없음. 원본 .codex 해시 불변

실제 화면에서 다음 문제를 찾았다.
1. 트리 항목의 UI 자동화 이름(= 화면 읽기 프로그램이 읽는 이름)이 `CodexBackupManager.App.ViewModels.Import.ImportProjectNodeViewModel` 같은 **클래스 이름**이다.
   그래서 자동화로 대화 행을 이름으로 찾거나 선택할 수 없었다.
2. 검색 칸에 보이는 자리 표시 문구가 없어 빈 상자만 보인다(접근성 이름 "대화 검색"은 있음).
3. 프로젝트 펼침 삼각형이 작업 폴더 상자 중간("이 PC" 줄 옆)에 떠 있다.
4. 선택할 수 없는 대화의 체크박스가 흰색이라 선택 가능해 보인다. "이미 있음" 행에는 이 PC 위치가 행 안에 없다(오른쪽 상세에만 있음).
   사용자의 원래 혼란("가져왔는데 어디 갔지?")을 바로 푸는 정보라 행 안에 보여야 한다.
5. 편집 화면에 들어가면 오른쪽 상세가 "왼쪽에서 대화나 프로젝트를 선택하세요."로 비어 있다.
6. 머리 정보의 "앱 0.1.1.0"이 현재 앱 버전처럼 읽힌다. 실제로는 백업을 만든 앱의 버전이다.

9_1-15(간헐 실패 테스트)
- 9_2-2에서 PID로 자식을 찾게 고쳤지만, 관리 대화방 점검에서 **다시 간헐 실패**했다.
- 부하를 걸고 150회 재현하니 5회에서 방금 띄운 자식 cmd의 `MainModule` 경로를 아직 읽을 수 없어 `MainModulePath`가 null이었다.
- 실제 원인은 목록 순서가 아니라 **프로세스 초기화 타이밍**이다.
- 제품 판정은 이름("codex")으로도 잡으므로 영향이 없다.

## 2. 이번 범위 (이것만 한다)

### 9_1-15 재수정
- 테스트가 자식 프로세스 초기화를 기다리게 한다. 예: 자식 PID의 `MainModulePath`가 채워질 때까지 목록을 짧은 간격으로 다시 읽고, 상한 수 초 안에 채워지면 검증한다.

### 9_2b 백업 속 대화 내용 미리보기(설계 §2.6)

- **9_2b-03** 가져오기 화면이 열려 있는 동안 미리보기용 BackupReader를 **한 번만** 열어 재사용하고, 화면을 닫거나 다른 파일을 열 때 Dispose한다.
  - backup identity 검증(Plan 생성 시 SHA-256)은 이와 별개로 지금처럼 동작한다.
  - 미리보기 reader가 열려 있어도 Plan 생성과 Apply가 막히지 않아야 한다(파일 공유 모드 확인).
- **9_2b-04** 대화를 선택하면 백그라운드에서 transcript를 만든다.
  - 선택이 바뀌면 이전 작업을 취소한다. 최근 3개는 캐시한다(LRU).
  - 분기 대화는 메인 Viewer처럼 조상 내용까지 이어서 보여준다(BackupCatalogReader의 체인 사용).
  - 백업에 없는 조상 등으로 일부만 보이면 그 사실을 한 줄로 알린다.
- **9_2b-05** 오른쪽 상세의 "대화 내용" 자리에 메인 Viewer와 **같은 렌더링**을 재사용한다(ConversationMessageViewModel + MarkdownLite + FlowDocumentBinding + 가상화 목록, User/Assistant 모양 동일).
  긴 대화도 멈추지 않게 한다.
- 안전: 미리보기는 읽기 전용이다. **임시 파일을 만들지 않는다. Codex Home에는 아무것도 쓰지 않는다.** 로그에 대화 원문·제목을 남기지 않는다.

## 4. 공통 규칙

- 원본 보호: 실제 C:\Users\User\.codex에는 절대 쓰지 않는다. 앱을 띄우거나 스크래치로 읽었다면 작업 전후 4개 파일 SHA-256을 비교해 보고한다

- 복제본 주의: .codex 복제본을 CODEX_HOME으로 지정해 codex.exe를 실행하지 않는다.

- 로그 redaction: 경로·제목·원문을 로그에 남기지 않는다.
- TDD: 결함 수정(9_1-15)은 재현 결과를 보고한다. 새 기능 테스트에서 RED를 못 봤으면 못 봤다고 적는다.
- 빌드 경고 0 · 오류 0, 전체 테스트 통과. 불확실한 것은 추측하지 말고 보고서 7번에 질문으로 남긴다.
- 참고: 관리 대화방은 점검 때 실제 앱을 UI 자동화로 띄워 캡처한다. 트리와 버튼이 표시 이름으로 찾아지도록(9_2-23) 신경 써 달라.
