## 1. 배경

- 지금 가져오기 화면(ImportPreviewViewModel + MainWindow.xaml의 미리보기 영역)은 내부 용어 나열이다.
  신규/동일/업데이트 가능 개수, "가져오기 계획 생성 완료 — 충돌 없음(적용 전 최종 검사가 필요합니다)" 같은 문구가 그대로 나온다.
- 사용자가 실제로 겪은 문제는 두 가지다. 대화를 가져왔는데 어디로 들어갔는지 몰랐고, 다시 가져오기를 하니 아무 일도 없어 "불러오기가 안 된다"고 판단했다.
  실제로는 "기타 대화"로 들어갔고, 두 번째는 이미 있어서 할 일이 없었다.
- 이번 화면이 해결할 것
  - 메인 목록과 같은 프로젝트→대화 트리 + 체크박스로 고르고, 프로젝트마다 작업 폴더를 그 자리에서 지정한다.
  - 적용 전에는 무엇이 어디로 들어가는지, 적용 후에는 무엇이 어디로 들어갔는지를 평범한 말로 보여준다.
- App은 아직 기존 ImportPlanBuilder.Build(preview, path)를 쓴다. 그래서 Diverged가 하나라도 있으면 Apply 전체가 막힌다.
  이번에 선택 오버로드 Build(preview, path, choices)로 바꾼다.

## 4. 공통 규칙

- 원본 보호: 실제 C:\Users\User\.codex에는 절대 쓰지 않는다. 앱이나 스크래치로 읽었다면 작업 전후 4개 파일 SHA-256을 비교해 보고한다
  (state_5.sqlite, session_index.jsonl, .codex-global-state.json, config.toml).
- 복제본 주의: .codex 복제본을 CODEX_HOME으로 지정해 codex.exe를 실행하지 않는다.
- MVVM: 판단은 Core에 두고 ViewModel은 표시와 선택 수집만 한다. View code-behind에 상태를 두지 않는다. 외부 MVVM 프레임워크나 NuGet 패키지를 추가하지 않는다.
- 스타일: App.xaml의 기존 다크 테마 리소스를 쓴다. 새 색이 필요하면 리소스로 추가한다. 키보드 포커스가 보이고, 창 폭이 좁아도 겹치지 않게 한다.
- 로그 redaction: 경로·제목·원문을 로그에 남기지 않는다(개수와 enum만).
- TDD: 결함 수정(9_1-15)은 RED를 볼 수 있으면 보고, 못 보면 못 봤다고 적는다. UI 로직은 VM 테스트로 검증한다.
- 빌드 경고 0 · 오류 0, 전체 테스트 통과. 불확실한 것은 추측하지 말고 보고서 7번에 질문으로 남긴다.
