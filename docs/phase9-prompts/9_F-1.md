### 9_4-10 되돌리기 사후 검증에 fresh catalog 확인 추가 (9_4-1 보고 Q5)
- 되돌리기 사후 검증이 지금은 행·파일·global-state를 직접 확인한다. 여기에 fresh catalog 확인을 더한다(Apply 사후 검증과 같은 방식).
  - 되돌린 새 대화가 카탈로그에 없다.
  - 이어받기를 되돌린 대화와 옮기기를 되돌린 대화가 원래 그룹(가져오기 직전 위치)에 있다.
  - 지운 프로젝트가 ProjectDirectory에 없다. 남겨 둔 프로젝트는 그대로 있다.
- 실패하면 기존 실패 경로(되돌리기 Snapshot으로 Rollback)를 탄다.
- 테스트: 정상 되돌리기에서 확인 통과. 임시 변형(예: 그룹 확인 일부러 틀리게)으로 Rollback 경로가 타는지 RED 확인.

## 3. 안전 규칙
- 실제 C:\Users\User\.codex와 실제 Snapshot 폴더에는 쓰지 않는다. 작업 전후 4개 파일 SHA-256을 비교해 보고한다(state_5.sqlite, session_index.jsonl, .codex-global-state.json, config.toml). 사용자가 Codex를 쓰는 중이면 열지 않았다는 사실과 수정 시각만 보고한다.
- 사용자가 실험 빌드(artifacts\test-*)나 개발 빌드 앱을 실행 중일 수 있다.
  - 그 프로세스를 종료하지 않는다. artifacts 폴더는 건드리지 않는다.
  - 빌드가 잠기면 저장소를 bin/obj/.git 없이 스크래치로 복사해 빌드·테스트하고 그렇게 보고한다.
- 로그에 경로·제목·이름을 남기지 않는다. 빌드 경고 0 · 오류 0. 불확실하면 추측하지 말고 보고서 7번에 질문으로 남긴다.
