## 2. 이번 범위

### 9_5-07 [새 폴더 만들기] 버튼
- 위치: 작업 폴더 영역의 [폴더 선택…]/[다른 폴더…] 옆. 백업 프로젝트 행과 백업 "기타 대화" 그룹 모두에 둔다.
  폴더를 바꿀 수 있는 상태(`CanChangeFolder`)일 때만 활성화한다.
- 동작
  1. 누르면 `<새 폴더 위치>\<폴더 이름>`을 즉시 만든다(없으면 기준 폴더도 만든다).
  2. 그 뒤는 사용자가 그 폴더를 [폴더 선택…]으로 고른 것과 똑같이 처리한다(같은 코드 경로를 쓴다). 결과는 CreateNew다.
  3. 새 프로젝트 이름 칸에는 **정리 전 원래 이름**(백업 프로젝트 이름 또는 대화 제목, 앞뒤 공백 제거)을 넣는다.
     폴더 이름에 붙은 ` (2)`나 `_` 치환이 프로젝트 이름에 들어가지 않게 한다. 사용자가 이름 칸을 고칠 수 있는 것은 그대로다.
- 원래 이름
  - 백업 프로젝트 행: 백업 프로젝트 표시 이름
  - 백업 "기타 대화" 그룹: 그 그룹에서 지금 체크된 대화가 1개면 그 제목, 0개 또는 여러 개면 `가져온 대화 yyyy-MM-dd`(이 PC 날짜)
- 폴더 이름 정리 규칙(순수 함수로 두고 단위 테스트한다. 위치는 App.Services 또는 Backup.Import 중 적절한 곳을 골라 보고)
  - `Path.GetInvalidFileNameChars()`와 `<>:"/\|?*`, 제어 문자 → `_`
  - 앞뒤 공백과 끝의 점(`.`)을 지운다
  - 예약 이름(CON, PRN, AUX, NUL, COM1~COM9, LPT1~LPT9, 대소문자 무시, 확장자가 붙어도 해당)이면 뒤에 `_`
  - 80자(UTF-16 코드 단위)까지 자른다. 서로게이트 쌍을 반으로 자르지 않는다. 자른 뒤 끝 공백·점을 다시 지운다
  - 결과가 비면 `Codex 프로젝트`
  - 같은 이름의 파일이나 폴더가 이미 있으면 ` (2)`, ` (3)` … 을 붙인다. **기존 폴더를 재사용하지 않는다.** 상한(예: 999)을 넘으면 실패로 처리한다
- 실패(권한, 경로 길이, 기준 폴더가 파일인 경우 등) 시에는 목적지를 바꾸지 않는다. 그 행에 이렇게 표시한다: "폴더를 만들지 못했습니다(<짧은 사유>). [폴더 선택…]으로 직접 골라 주세요."
  사유에는 예외 형식 이름 정도만 쓰고 경로를 넣지 않는다.

### 9_5-08 새 폴더 위치
- 기본값: `Environment.GetFolderPath(SpecialFolder.MyDocuments)` + `ChatGPT`. OneDrive로 옮겨진 문서 폴더도 이 API가 알려 주는 곳을 쓴다.
- `AppSettings.NewProjectFolderBase`(string?, 없으면 기본값)를 추가한다. 설정 파일 버전은 올리지 않는다(없는 필드는 null로 읽히므로 호환). 기존 설정 파일이 깨지지 않는지 테스트한다.
- 가져오기 화면 작업 폴더 영역 근처에 "새 폴더 위치: <경로> [변경…]"을 한 줄로 표시한다.
  [변경…]은 기존 폴더 선택 대화상자를 쓰고, 고르면 설정에 저장한다.
- 거부 조건(기준 폴더로 쓰지 않고 안내 문구를 띄운다)
  - 절대 경로가 아님
  - 현재 Codex Home 안이거나 Codex Home 자체(canonical 비교)
  - 이 앱의 데이터 폴더(%LOCALAPPDATA%\CodexBackupManager, Snapshot 루트) 안
- VM은 테스트할 수 있게 기준 폴더 제공자와 폴더 생성기를 주입받는다(기존 생성자 주입 Func 패턴을 따른다). 테스트는 temp 폴더를 쓴다.

### 9_5-09 이 화면에서 만든 폴더 정리
- 이 화면(ImportWorkspaceViewModel 세션)에서 앱이 만든 폴더 경로를 기억한다. 기준 폴더를 새로 만들었다면 그것은 목록에 넣지 않는다(지우지 않는다).
- 다음 경우 그 폴더가 **완전히 비어 있으면**(파일과 하위 폴더 모두 0개) 지운다.
  - 그 행의 목적지를 [원래대로]나 [다른 폴더…]로 바꿀 때(바꾸기가 확정된 뒤에만)
  - 가져오기를 하지 않고 화면을 닫을 때(다른 백업 파일 고르기로 화면을 다시 시작할 때도 포함)
  - 가져오기가 실패했거나 Rollback된 뒤 화면을 닫을 때
- 삭제는 `Directory.Delete(path, recursive: false)`만 쓴다. 재귀 삭제는 절대 쓰지 않는다. 지우기 직전에 비어 있는지 다시 확인한다.
  실패하면 조용히 넘어가되 Warning 로그를 남긴다(경로 없이 개수만).
- 가져오기가 성공(Succeeded)했으면 그 적용에 쓰인 폴더는 남긴다(새 프로젝트의 루트다). 같은 화면에서 만들었지만 적용에 쓰이지 않은 폴더는 위 규칙대로 정리한다.
- 앱 종료 중이라 화면을 닫는 경우는 최선만 다한다(종료를 막지 않는다).

### 9_5-10 결과 화면의 이어받기 대화 표시 (9_5-1 보고 Q2)

## 4. 안전 규칙
- 실제 C:\Users\User\.codex에는 절대 쓰지 않는다. 작업 전후 4개 파일 SHA-256을 비교해 보고한다(state_5.sqlite, session_index.jsonl, .codex-global-state.json, config.toml).

- 폴더 삭제는 비재귀, 이 화면에서 앱이 만든 폴더, 삭제 직전 비어 있음 재확인. 세 조건을 모두 만족할 때만 한다.
- 로그에 경로, 폴더 이름, 프로젝트 이름, 대화 제목을 남기지 않는다(개수와 결과만).
