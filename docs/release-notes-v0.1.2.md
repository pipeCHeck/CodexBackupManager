# Codex Backup Manager 0.1.2

첫 공개 배포(v0.1.2) 릴리스 노트입니다. 이 문서는 GitHub Release 본문으로 그대로 쓸 수 있도록
작성했습니다 — 실제 Tag/Release 업로드는 사용자가 이 작업 트리를 검토·커밋한 뒤 직접 진행합니다.

## 이게 무엇인가요

OpenAI Codex(CLI/Desktop)의 로컬 프로젝트·대화 데이터를 조회하고, 선택해서 `.codexbackup` 파일로
내보내고, 다른 PC에서 불러와 안전하게 복원하는 Windows 데스크톱 프로그램입니다. .NET 런타임
설치가 필요 없는 self-contained **폴더형** 배포입니다 — `CodexBackupManager.exe`와 실행에
필요한 DLL/런타임 파일이 전부 한 폴더 안에 들어 있고, 그 폴더를 통째로 옮겨서 실행하면 됩니다
(v0.1.1까지는 single-file EXE 하나였지만, v0.1.2부터 폴더형으로 배포 형태를 바꿨습니다 — 기능은
동일합니다).

## 주요 기능

- **Codex Home 자동 탐색**: `CODEX_HOME` 환경 변수 → `%USERPROFILE%\.codex` → 저장된 경로 →
  수동 지정 순으로 확인합니다.
- **프로젝트/대화 목록**: 실제 rollout(JSONL) 구조를 파싱해 프로젝트별로 대화를 묶어 보여줍니다.
  세그먼트/분기(조상 체인)까지 반영합니다.
- **대화 열람(Viewer)**: User/Assistant 메시지를 구분해 표시합니다.
- **선택 & Export**: 프로젝트 전체 또는 개별 대화를 선택해 하나의 `.codexbackup`(ZIP 기반, SHA-256
  체크섬 포함) 파일로 내보냅니다.
- **Import Preview**: 백업 파일을 열면 적용 전에 내용(프로젝트/대화 수, 원본 경로, 현재 상태)을
  먼저 보여줍니다. 실제 내용 비교로 New/Identical/이어짐(IncomingAhead)/분기(Diverged) 등을
  판정합니다 — 타임스탬프가 아니라 rollout 바이트 자체를 비교합니다.
- **프로젝트 경로 재매핑**: 다른 PC에서 프로젝트 실제 경로가 다르면 폴더를 다시 지정할 수
  있습니다.
- **안전한 Apply**: Codex 종료 확인 → 최신 상태 재확인(preflight) → 복구용 Snapshot 생성 → 실제
  적용 → 결과 검증까지 자동으로 수행하고, 중간에 실패하면 자동으로 이전 상태로 되돌립니다.

## 안전성 설계

이 프로그램의 최우선 원칙은 "Codex 데이터를 많이 건드리는 것"이 아니라 **사용자의 기존 Codex
데이터를 절대 잃지 않는 것**입니다.

- 탐색/Viewer/Export/Import Preview는 전부 **Read-Only**입니다 — 이 경로에서는 Codex Home 아래
  어떤 파일도 수정하지 않습니다.
- 실제 write는 **Apply**에서만, 그것도 다음 순서를 전부 거친 뒤에만 일어납니다: Codex 실행 여부
  확인 → 최신 상태 재확인 → 물리적으로 안전한지 재확인(안전을 증명할 수 없으면 적용 자체를
  0건으로 거부) → 현재 상태의 복구용 Snapshot 생성 → 실제 적용 → 결과 검증.
- rollout 파일에 대한 모든 write(신규 생성/이어붙이기)는 임시 파일에 먼저 쓰고 검증한 뒤
  원자적으로(atomic) 교체합니다 — 쓰는 도중 프로세스가 강제 종료돼도 원본은 반쯤 쓰인 상태가
  되지 않습니다.
- Apply 도중 실패하거나 취소하면 Snapshot을 기준으로 자동 Rollback합니다. 프로세스 자체가 죽어도
  (정전, 강제 종료 등) 다음 실행이 "완료되지 못한 이전 작업"을 감지해 사용자에게 복구를
  안내합니다 — 사용자 모르게 자동으로 덮어쓰지 않습니다.
- 지원하지 않는(안전을 증명할 수 없는) 대화는 적용 자체를 전체 차단합니다: 서로 다른 두 PC에서
  각각 앞서간 대화(Diverged)의 자동 병합, 압축 rollout(`.jsonl.zst`)의 갱신 등은 v0.1.2에서
  지원하지 않습니다.
- 같은 프로그램을 두 번 실행해도 같은 Codex Home에 동시에 적용을 시도할 수 없습니다(프로세스 간
  잠금).
- 개인 대화 원문은 로그에 기록하지 않습니다.

## 사용법

1. 압축을 풀어 나온 `CodexBackupManager-v0.1.2-win-x64` 폴더 안의 `CodexBackupManager.exe`를
   실행합니다 — 설치가 필요 없습니다(폴더 안의 다른 파일들은 그대로 두어야 합니다).
2. Codex Home을 자동으로 찾지 못하면 [폴더 선택]으로 직접 지정합니다.
3. 프로젝트/대화 목록에서 내보낼 항목을 선택하고 [내보내기]를 눌러 `.codexbackup` 파일을
   만듭니다.
4. 다른 PC(또는 같은 PC)에서 이 프로그램을 실행하고 [백업 불러오기]로 그 파일을 선택하면 내용을
   미리 볼 수 있습니다.
5. 필요하면 프로젝트 경로를 재지정한 뒤, [적용]을 누릅니다 — **적용 전에 Codex를 완전히
   종료해야 합니다.**
6. 적용이 끝나면 Codex를 다시 실행해 복원된 대화를 확인/재개할 수 있습니다.

자세한 사용 안내는 배포 ZIP에 동봉된 `README.txt`(`docs/dist-readme.txt`)를 참고하세요.

## 알려진 제한 사항

- Windows 10/11 x64 전용입니다.
- Diverged(두 PC에서 각각 앞서간) 대화의 자동 병합/교체/복사본 가져오기는 아직 지원하지 않습니다
  — 이런 대화는 적용 전체가 안전하게 차단됩니다.
- 압축된 rollout(`.jsonl.zst`)의 갱신(Update)은 지원하지 않습니다(새로 만드는 것은 지원합니다).
- `local_image`를 제외한 일부 첨부(attachment) 파일은 백업에 포함/복원되지 않습니다.
- 로컬에 아직 없는 새 프로젝트를 자동으로 만들지 않습니다.
- Codex Desktop 앱 사이드바에 프로젝트별로 정확히 묶여 보이는지는 아직 별도로 검증하지
  못했습니다(Core/CLI 기준 데이터는 정확합니다).
- 프로세스 간 잠금은 같은 Windows 로그인 세션 범위에서만 유효합니다.
- Snapshot(복구용 백업, `%LOCALAPPDATA%\CodexBackupManager\Snapshots\`)은 자동으로 삭제되지
  않습니다 — 필요하면 충분히 확인한 뒤 직접 정리하세요. 완료되지 못한(Applying) 상태로 표시된
  Snapshot은 프로그램이 [이전 상태로 복구]를 안내하기 전까지 직접 지우지 마세요.
- 이 배포판은 code-signing되지 않았습니다 — 첫 실행 시 Windows SmartScreen이 경고를 띄울 수
  있습니다([추가 정보] → [실행]으로 진행 가능).
- .NET이 전혀 설치되지 않은 클린 Windows 환경에서의 실기 검증은 이번 릴리스에서 수행하지
  못했습니다(개발 환경에는 이미 .NET SDK가 설치되어 있었습니다) — self-contained publish
  구조상 동작해야 하지만, 직접 확인된 사실은 아닙니다.

## SHA-256 확인 방법

배포 ZIP과 같은 폴더의 `SHA256SUMS.txt`에 해시가 있습니다. PowerShell에서 다음처럼 비교하세요.

```powershell
Get-FileHash .\CodexBackupManager-v0.1.2-win-x64.zip -Algorithm SHA256
```

출력된 해시가 `SHA256SUMS.txt`에 적힌 값과 정확히 같아야 합니다.
